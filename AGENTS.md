# Инструкции для агентов

Этот файл действует для всего репозитория. Перед изменением вложенного модуля
проверь наличие его собственного `AGENTS.md`. Явные указания пользователя имеют
приоритет над рекомендациями этого файла.

## Проект и стек

Dream House — frontend для управления строительными проектами и продажами:
ПТО, сметы, заявки на материалы, закупки, склады, юридические документы,
задачи, платежи, отчёты, клиенты и объекты недвижимости.

- React 19, TypeScript 5.9, Vite 7; проект использует ES modules.
- Redux Toolkit и React Redux для состояния; React Router для маршрутов.
- MUI, Tailwind CSS 3 и CSS проекта для интерфейса.
- React Hook Form для форм; Socket.IO для уведомлений.
- Алиас `@/` указывает на `src/` и настроен в TypeScript и Vite.
- Рабочее окружение — Windows/PowerShell. В Docker используется Node.js 22.

## Порядок работы

- Начинай с `git status --short` и изучения целевого модуля и его вызовов.
  Существующие изменения и новые файлы считай работой пользователя; сохраняй их.
- Делай изменения в рамках задачи. Не форматируй весь репозиторий и не исправляй
  соседние модули без необходимости для запрошенного результата.
- Следуй стилю соседнего кода. Сохраняй русские тексты интерфейса и UTF-8.
- Используй `rg` для поиска. Не редактируй `node_modules/` и `dist/` вручную.
- Не выполняй сброс, очистку, commit, push или публикацию без соответствующего
  запроса пользователя. Для обычных правок и проверок дополнительное согласование
  не требуется.
- В итоговом ответе кратко укажи результат, проведённые проверки и ограничения.
  Не называй непроведённые проверки успешными.

## Реализация

- Размещай бизнес-логику в соответствующем `src/features/`. Переиспользуемый UI
  добавляй в `src/components/ui/`, общие функции — в `src/utils/`.
- Используй функциональные компоненты, существующие UI-компоненты и стили.
  Сохраняй состояния загрузки, ошибок, пустых данных, фильтры и пагинацию.
- Для Redux используй `useAppDispatch` и `useAppSelector` из `src/app/store.ts`.
  Новые slices регистрируй в `src/app/rootReducer.ts`; маршруты — в router.
- Сохраняй строгую типизацию. Для новых контрактов предпочитай явные типы и
  `unknown` с проверкой вместо `any`; импорты типов оформляй через `import type`.
  Учитывай `verbatimModuleSyntax` и `erasableSyntaxOnly` в конфигурации TypeScript.
- Соблюдай правила React Hooks. Для подписок, таймеров и сетевых соединений
  предусматривай очистку и повторное выполнение эффектов в StrictMode.
- Сохраняй существующие контракты backend: поля, статусы, идентификаторы,
  параметры маршрутов и формат ответа. Проверяй используемые типы и справочники;
  не придумывай endpoints или значения статусов.
- Для денежных значений, количеств и дат используй существующие утилиты.
  Проверяй округление, пустые значения и нули при изменении расчётов.

## API, авторизация и конфигурация

- Обычные API-запросы проводи через `src/utils/apiRequest.ts`.
  Для специализированных запросов и файлов используй существующий слой
  `authenticatedFetch` из `src/features/auth/authSession.ts`.
- Не дублируй refresh, хранение токенов и обработку выхода в бизнес-модулях.
  Сохраняй согласование сессии между вкладками и защиту от поздних ответов.
- Не передавай refresh-токен сервису отчётов или Socket.IO. Не помещай токены
  и пароли в Redux, логи, документацию или сообщения. Redux DevTools отключён
  из-за паролей в аргументах auth actions; не включай его без устранения причины.
- Адреса сервисов берутся из `VITE_API_URL`, `VITE_REPORTS_URL`,
  `VITE_SOCKET_URL`, `VITE_SOCKET_PATH`. Не зашивай адреса окружений в код.
- Не изменяй `.env` без необходимости для задачи и не копируй его значения
  в ответ. Любые `VITE_*` доступны в клиентской сборке и не подходят для секретов.
- Для Docker переменные Vite задаются при сборке; смена адресов требует
  пересборки. Проверяй настройки по `Docker.md` и `.env.docker.example`.

## Команды и проверка

Выполняй команды из корня проекта. В репозитории есть `yarn.lock` и
`package-lock.json`; Docker использует `yarn.lock`. Не перегенерируй оба lockfile
и не меняй менеджер пакетов попутно. Зависимости устанавливай только при необходимости.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Dev-сервер Vite, настроенный порт 5173 |
| `npm run build` | Проверка TypeScript (`tsc -b`) и production-сборка |
| `npm run lint` | ESLint всего проекта |
| `npx --no-install eslint src/path/File.tsx` | Проверка конкретных изменённых TS/TSX-файлов |
| `npm run preview` | Просмотр готовой сборки |
| `node tests/auth-client.test.cjs` | Тесты авторизации без реального backend |

- После изменений TypeScript, конфигурации или зависимостей запускай сборку
  и ESLint затронутых TS/TSX-файлов. Для широких изменений запускай общий lint.
- При изменениях авторизации, API-обёртки или синхронизации сессии запускай
  тесты авторизации. Скрипта `npm test` в `package.json` сейчас нет.
- Проверяй изменённые сценарии UI, когда доступен браузер и нужное окружение.
  Если ручная проверка недоступна, укажи это в результате.
- Добавляй тесты для существенной логики и регрессий; для изменения только
  документации достаточно проверить текст и diff.
- При ошибках проверок выясни, связаны ли они с задачей. Не скрывай ошибки
  отключением правил и не включай посторонние исправления без необходимости.
- Перед завершением просмотри diff и выполни `git diff --check`.
